## 2. What changed
**Project setup**
- Created the project rules (`CLAUDE.md`), `checkpoints/LINEAGE.md`, and this checkpoint with its explanation. (First drafted in the claude.ai Project, then moved into the local project folder the same day. The folder is the source of truth.)
- Platform decided: **PWA** (matches the workout tracker), local-first, with a future move to full-stack on AWS.

**Product decisions**
- Name: **Atomic** (after *Atomic Habits*).
- Naming system: Atom (task/habit), Molecule (goal), Element (area, 2-letter symbol), Isotope (subcategory), State (flow state/mood), Orbit (time block).
- Screens: Today, Upcoming (week), Habits (streaks + heatmap), Goals/Molecules, Weekly Review.
- Interactions: tap `[ ]` → `[✓]` checkbox to complete, long-press menu (Skip without breaking streak, Partial, Snooze, Note), +1 counter habits, timer habits, quick-add text bar, flexible repeats ("3x per week"). **No swipes.**
- Motivation: streak freezes, energy tags, morning top-3 / evening one-liner, home-screen shortcut (widget-like features are limited on PWAs, to be revisited at full-stack).
- Orbits: time blocks on a day timeline. Atoms can sit inside an Orbit, and later an Orbit can switch the State automatically.
- States: in-app modes that change visible Elements/Atoms, UI minimalism and theme. The future NFC deck station and app-blocking are out of scope for PWA. Those need phone-level features (e.g. phone automations triggered by NFC tags, or a native app) and are deferred, but the data model reserves room for them.
- Design: dark terminal screen, muted secondary tones, phosphor green by default with amber and red themes, typewriter body font plus terminal header font.

**Draft data model (sync-ready)** *(superseded in detail by CLAUDE.md § Architecture)*
Every record: `id` (UUID), `sourceApp` ("atomic" | "workout"), `createdAt`, `updatedAt`, `deletedAt` (soft delete).
- **Element**: symbol, name, color
- **Isotope**: elementId, name
- **Atom**: kind (task | habit), title, elementId, isotopeId?, moleculeId?, orbitId?, repeat rule, target (count/timer), energy, completions[] (date, status: done | skipped | partial)
- **Molecule**: title, elementId, target date, linked atom ids
- **Orbit**: title, start/end, repeat rule, stateId?
- **State**: name, visible elements, UI level, theme, reserved `externalTriggers` (NFC etc.)
- Shared/synced items: anything in the Fitness Element (`Fi`) is eligible for workout-app sync. Conflicts resolve by newest `updatedAt`.

**Historical Milestones**

**Cumulative Capabilities**
Atomic does not run yet. It exists as a plan for a personal habit and to-do tracker built as an installable web app that works offline. The plan organizes life into Elements, such as Fitness or Career, each split into Isotopes like Strength or Cardio. Inside them sit Atoms, the individual tasks and habits you tick off, and Molecules, the bigger goals those Atoms build toward.

The day can be divided into Orbits, blocks of time like work hours, a date or an event. States, such as Study, Workout or Do Not Disturb, will change how minimal the app looks and what it shows. The look is an old-school terminal: dark screen, typewriter lettering, green by default.

Every record is designed from the start to carry the labels a future sync needs. That will let Atomic and the workout tracker share goals, and marking one done in either app will update both once the cloud side is built on AWS.
