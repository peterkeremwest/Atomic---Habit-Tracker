# v0.2.6 — What happened, in plain language

Before this version, only the shared list had an × next to each item and a visible box for adding items, and no list could change an item's text. If you misspelled "milk" you had to delete it and type it again. Tasks that had steps, like the "Updates" checklist, had neither an add box nor a remove button. Now every item in every kind of list has a pencil and an ×: lists made with `#list`, notes, the steps of a task, the costs of an expense list and shared lists. The × removes the item. The pencil opens a small sheet with the text already filled in, and saving it replaces the old text. An expense cost is edited as one line, such as `oil change $35`, and Atomic splits it back into a name and an amount, so the total updates by itself. Both actions can be undone for five seconds, like everything else in the app. Tasks that have steps also got a "+ add step" box, and an expense list keeps its add box after you mark it paid. Regular `#list` lists, notes and shared lists already had that box.

Removing items follows the same rule as checking them. A list or a task with steps counts as finished when every remaining item is checked, so removing the last unchecked item can finish it. If you remove every step from a task, it becomes a plain task again and keeps whatever done state it had. Notes and expense lists never change their done state when you edit their items, because notes never finish and an expense list is marked paid by hand.

The second change is about two devices disagreeing. Atomic keeps a copy of your data on each device and in the cloud. When two copies of the same record differ, it keeps the one that was saved last and drops the other. That rule is simple, but it has a flaw. If your PC browser holds an old copy of a task and saves anything on it (dragging it, pinning it, moving it), that copy becomes the most recently saved one, and it wins even though it still says the task is unfinished. A task you checked on your phone can then look unchecked again. To close that gap, every check or uncheck of a task now records its exact time and which device did it. When two copies are merged, the check state comes from whichever copy has the later check or uncheck time, while everything else about the record still follows the newest save. The result is saved as a new edit and sent to the cloud, so all devices end up with the same answer. A deliberate uncheck on any device still wins, because it carries a newer time. Tasks you checked before this version have no time recorded, so they don't get this protection.

The same record also makes problems easier to trace. Search results for a finished task now read like "done Oct 10 · checked Oct 10, 8:04 PM on phone". This was added because a task checked on October 10 turned up as done on October 15, and the code review could not explain why. If it happens again, that line shows when and from which device the task was last checked. Nothing changed in AWS: the cloud stores each task as an opaque record, so the new fields travel through it without any change to the stack.

One thing worth knowing about releases: right after this version was deployed, the first load in the built-in browser failed with a message about a missing `openItemEdit`, and the next load was fine. That looks like a file served from an older copy during the rollout, not a bug in the code. If your phone ever shows "booting…" after an update, close the app fully and open it again.
