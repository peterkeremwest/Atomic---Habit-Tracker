# v0.1 — What happened, in plain language

Before this checkpoint, Atomic was only an idea: "a habit tracker, like my workout app." There was no company yet, just someone thinking about opening one. Now the company has been registered. It has a name, a business plan, a filing system and a rulebook for how work gets recorded, but no storefront has been built and no staff have been hired.

The business plan describes what the company will sell and how customers will experience it. Customers will walk into a storefront that looks like an old terminal: dark walls, green typewriter lettering, and plain checkboxes on the counter to tick off what they've done. Every task or habit is an Atom. Bigger goals are Molecules built from Atoms. The departments of the company are Elements like Fitness or Career, and each department has teams called Isotopes. The company's calendar is divided into Orbits, blocks of time like working hours or an evening out. The whole office can switch into different States, like a quiet "study hours" mode where only the relevant departments stay open.

The filing system was designed with a future branch office in mind: the workout tracker. Every file gets a permanent ID number, a stamp saying which branch created it, and a "last changed" date. Nothing is shredded; it's marked as retired instead. That matters because later the office PA system (AWS EventBridge) will get a private channel that only the two branches listen to. When a fitness goal is marked done in one branch, it's announced on that channel, the other branch updates its own files, and the date stamps tell each branch which version is newest.

The rulebook (CLAUDE.md) and the company history log (LINEAGE.md) follow the same habits as Forge, the workout tracker, and use the same glossary of company terms. Each milestone gets a numbered report, a plain-language summary like this one, and a single running history, so nobody has to re-read every old report to know where things stand. This first report is v0.1. The next step is choosing a building site (the project folder), a records room for the blueprints (the GitHub repository) and a storefront-leasing office (the hosting service) before the first storefront goes up.
