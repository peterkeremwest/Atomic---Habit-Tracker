# v0.2.3 — Pink colour option

## What changed
Atomic now has a fourth colour choice, **PINK**, next to GREEN, AMBER and RED in SETTINGS → DISPLAY.

## How it works
All of Atomic's colours live in one file, `public/css/theme.css`, as a small set of named values called **design tokens** (for example `--fg` for the main text colour, `--bg` for the background, `--dim` for secondary text). Every screen reads these names instead of hard-coding colours. Each theme is a block like `[data-theme="red"] { ... }` that redefines those same names.

When you tap a colour in SETTINGS, the app writes the choice into your settings and sets `data-theme="pink"` on the page's root element. The browser then applies whichever block matches, so every screen switches at once without any other code changing.

Adding pink therefore took two small edits:

1. **`public/css/theme.css`** — a new `[data-theme="pink"]` block with a hot-pink text colour (`#ff6ec7`), a near-black background with a slight pink tint, darker pinks for lines and secondary text, and amber kept as the warning colour so warnings still stand out.
2. **`public/js/views/system.js`** — `'pink'` added to the list of theme buttons shown in SETTINGS.

`--fg-rgb` is the same pink written as three numbers (red, green, blue). It exists so the glow and scanline effects can use the colour with transparency.

## Why the version number moved
`public/js/version.js` and the cache name in `public/sw.js` went from v0.2.2 to v0.2.3. The service worker keeps an offline copy of the app on your phone and only refreshes that copy when the cache name changes. Without the bump, an installed phone could keep showing the old stylesheet with no pink option.

## To see it
Once this is pushed to GitHub, Cloudflare rebuilds the site. Open the app, then reopen it once more so the new version takes over. Go to SETTINGS → DISPLAY → PINK.
